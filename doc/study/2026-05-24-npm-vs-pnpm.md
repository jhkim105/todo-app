# 2026-05-24 npm vs pnpm 차이점 핵심 요약

## 📌 1. 핵심 한 줄 정의
- **npm**: 패키지를 모듈 폴더마다 **물리적으로 무지성 복사**하는 1세대 도구.
- **pnpm**: 패키지를 글로벌 공통 저장소에 딱 1개만 받고, 개별 폴더에는 **하드 링크(Symlink)로 연결**하는 3세대 성능 특화 도구.

---

## 📊 2. 비교 요약 표 (Comparison)

| 비교 항목 | 🟥 npm | ⚡ pnpm |
| :--- | :--- | :--- |
| **의존성 저장 방식** | 중복 다운로드 & 복사 (디스크 낭비) | **단일 공통 저장소 & 링크 (용량 절약)** |
| **설정 속도** | 느림 (매번 물리적 디스크 I/O 발생) | **압도적으로 빠름 (복사 없음, 링크만 생성)** |
| **팬텀 디펜던시** | 발생 가능 (호이스팅으로 인한 보안 취약) | **원천 차단 (엄격한 node_modules 트리 유지)** |
| **모노레포 지원** | 별도 플러그인 또는 수동 설정 | **workspace.yaml 기본 내장 지원** |

---

## 🏗️ 3. 핵심 아키텍처 비교 (Concept)

### 🟥 npm (Hoisting & Duplicate)
- **방식**: 모든 패키지를 `node_modules` 루트로 끌어올림(Hoisting).
- **문제점**: `package.json`에 정의하지 않은 하위 의존성까지 임포트할 수 있게 되는 보안 허점(Phantom Dependency) 발생.

### ⚡ pnpm (Hard Link & Symlink)
- **방식**: 실제 파일은 `~/.pnpm-store`에 단 1개만 저장.
- **연결**: 각 프로젝트 `node_modules`에는 가상 저장소(`.pnpm/`)를 가리키는 중첩 심링크 구조만 배치.
- **장점**: 용량 대폭 절약 + 의존성 엄격 격리.

---

## 🚀 4. 핵심 명령어 매핑 (CLI Map)

| 작업 목적 | 🟥 npm | ⚡ pnpm |
| :--- | :--- | :--- |
| 패키지 설치 | `npm install` | `pnpm install` |
| 패키지 추가 | `npm install <pkg>` | `pnpm add <pkg>` |
| 스크립트 실행 | `npm run <script>` | `pnpm <script>` |
| 모듈 한정 실행 | (미지원) | `pnpm --filter <module> <cmd>` |
