# 📖 Strict Core-Focused Project Documentation Guidelines
> **AI 어시스턴트 전용: 프로젝트 문서화 핵심 요약 지침**

이 문서는 AI 코딩 비서(Antigravity)가 본 프로젝트 내에서 **기술 스터디(Study Document)** 및 **트러블슈팅(Troubleshooting Log)** 문서를 작성할 때 반드시 준수해야 하는 **통합 행동 양식 및 스타일 가이드라인**입니다.

---

## 🎯 1. 4대 대원칙 (Four Core Rules)

1. **극단적 간결함 (Extreme Conciseness)**:
   * 모든 설명은 **최대 2줄 이하**의 요약 형태로 제한합니다.
   * 긴 텍스트 설명 대신 **1:1 비교 표(Table)** 또는 **흐름도/구조도(Mermaid)**를 무조건 우선하여 설계합니다.
2. **명사형 종결 및 구어체 배제**:
   * 모든 문장은 명사형 종결 또는 구어체 배제(예: `~함`, `~로 해결`, `~방지`)를 기본으로 하며, 3인칭/객관적 어조만 사용합니다.
   * 서술형 어투(`~에 대해 알아보겠습니다`, `~했습니다`)는 일절 금지합니다.
3. **사설 및 미사여구 배제 (Zero Fluff)**:
   * 서론(인사말, 도입부)과 결론(소감, 맺음말)을 완전히 배제하고 문서의 첫 줄부터 즉시 핵심 대제목(H1)과 내용으로 시작합니다.
4. **로그 및 코드의 핵심 축약**:
   * 에러 메시지나 코드 수정 내역은 관련 없는 노이즈를 적극 생략(`...`)하여 **가장 핵심적인 10줄 내외**만 노출시킵니다.

## 📂 2. 문서별 상세 작성 가이드라인

### A. 기술 스터디 문서 (Study Document)

*   **저장 경로**: `doc/study/`
*   **파일명 규칙**: `YYYY-MM-DD-topic-slug.md` (예: `2026-05-24-npm-vs-pnpm.md`)
*   **문서 고정 템플릿**: 기술 스터디 문서는 항상 아래 **5단락 템플릿** 구조를 엄격히 복제하여 작성해야 합니다.
    1. `# YYYY-MM-DD [주제명] 핵심 요약` (대제목)
    2. `## 📌 1. 핵심 한 줄 정의` (핵심 요약)
    3. `## 📊 2. 비교 요약 표 (Comparison)` (특징 표 매핑)
    4. `## 🏗️ 3. 핵심 아키텍처 비교 (Concept)` (동작 원리 비교)
    5. `## 🚀 4. 핵심 명령어 매핑 (CLI Map)` (실전 치트시트)

### B. 트러블슈팅 문서 (Troubleshooting Log)

*   **저장 경로**: `doc/troubleshooting/`
*   **파일명 규칙**: `YYYY-MM-DD-error-slug.md` (예: `2026-05-24-pnpm-prisma-client-initialization-error.md`)
*   **문서 템플릿**: 유연하게 구성하되, 아래 **2가지 필수 요소(Issue, Resolution)**는 무조건 명확히 분리하여 포함해야 합니다.
    1. **🚨 발생한 문제 (Issue)**: 노이즈가 제거된 에러 메시지/로그와 발생 증상을 10줄 이내로 서술
    2. **🛠️ 해결 프로세스 (Resolution)**: 문제를 해결한 핵심 명령어 또는 코드 수정 분량(Git Diff 등) 제시
    *   *(권장 구조)*:
        *   `# YYYY-MM-DD [에러/이슈 명]` (H1 대제목)
        *   `## 🚨 1. 발생한 문제 (Issue)` (필수)
        *   `## 🔍 2. 원인 분석 (Root Cause)` (선택/간략히)
        *   `## 🛠️ 3. 해결 프로세스 (Resolution)` (필수)
        *   `## 💡 4. 오늘의 배움 (Key Takeaways)` (선택/1-2줄 요약)

## 🛠️ 3. AI 컨텍스트 주입 지침

AI 어시스턴트는 이 대화방 안에서 사용자가 **"학습 문서 추가해줘"**, **"기술 정리해줘"**, **"에러 해결 일지 작성해줘"**, **"트러블슈팅 정리해줘"** 라고 요청할 경우, 본 지침 파일([project-documentation-guidelines.md](doc/guidelines/project-documentation-guidelines.md))을 스스로 자동 확인(Read)하고 **이 규칙카드에 정의된 요약/표 형태의 포맷을 100% 강제 준수**하여 문서를 생성해야 합니다.
